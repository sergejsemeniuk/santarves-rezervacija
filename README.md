# Кабинет интерактивных кубов — бронирование

Приложение для бронирования учителями времени в кабинете с интерактивными кубами.
Данные хранятся в Firebase Firestore и обновляются в реальном времени у всех — как только
кто-то бронирует или отменяет слот, остальные видят это сразу, без перезагрузки страницы.

## 1. Настройка Firebase (один раз)

1. Зайти на https://console.firebase.google.com и создать новый проект (Add project).
2. В меню слева открыть **Build → Firestore Database → Create database**.
   Выбрать любой регион (ближайший, например `eur3`) и режим **Production mode**.
3. Открыть вкладку **Rules** в Firestore и вставить содержимое файла `firestore.rules`
   из этого проекта → Publish.
4. В настройках проекта (шестерёнка → **Project settings**) в разделе **Your apps**
   нажать **Add app → Web (`</>`)**, дать любое имя.
5. Firebase покажет объект `firebaseConfig` — скопировать значения в файл
   `src/firebase.js` (в этом проекте) на место `"ВСТАВЬ_СЮДА"`.

Это не секретные данные — они и так видны в коде браузера у всех пользователей.
Реальная защита — это правила в `firestore.rules`.

## 2. Запуск локально

```bash
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173` — можно проверить, что бронирование работает
и сохраняется (открой в двух вкладках, чтобы увидеть обновление в реальном времени).

## 3. Публикация — два варианта

### Вариант А: Netlify (проще всего)

1. Залить проект в репозиторий на GitHub (см. ниже, шаг "Загрузка на GitHub").
2. Зайти на https://app.netlify.com → **Add new site → Import an existing project**.
3. Выбрать репозиторий, Netlify сам определит настройки Vite:
   - Build command: `npm run build`
   - Publish directory: `dist`
4. Нажать Deploy. Через минуту будет готова ссылка вида `https://имя.netlify.app` —
   можно её раздавать учителям.
5. Дальше любой `git push` в репозиторий автоматически пересобирает и обновляет сайт.

### Вариант Б: GitHub Pages

1. В файле `vite.config.js` замени `base: "/cube-room-booking/"` на
   `base: "/название-твоего-репозитория/"`.
2. Загрузить проект в репозиторий на GitHub (см. ниже).
3. В настройках репозитория: **Settings → Pages → Source** выбрать **GitHub Actions**.
4. Готово — в проекте уже лежит `.github/workflows/deploy.yml`: при каждом
   `git push` в ветку `main` сайт будет собираться и публиковаться автоматически.
5. Ссылка появится в **Settings → Pages** после первого успешного деплоя
   (обычно `https://твой-логин.github.io/название-репозитория/`).

### Загрузка на GitHub (если ещё не сделано)

```bash
git init
git add .
git commit -m "Кабинет кубов: бронирование"
git branch -M main
git remote add origin https://github.com/ТВОЙ-ЛОГИН/НАЗВАНИЕ-РЕПО.git
git push -u origin main
```

## Важно про доступ

Ссылка на приложение (Netlify или GitHub Pages) — публичная, вход не требуется.
Любой, у кого есть ссылка, может бронировать и отменять брони — как и договаривались,
без логинов и паролей. Если позже понадобится ограничить доступ (например, только
учителям школы), можно будет добавить Firebase Authentication — это отдельная
дополнительная настройка.
